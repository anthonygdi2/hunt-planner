# Restructure and redesign: plan

Status: in progress. Started October 26, 2026. Target shape: `docs/ARCHITECTURE.md`. UI spec: `docs/design/`.

Claude Code works through the phases in order, one at a time, and updates the Progress log at the bottom after each one. A new session reads this file, finds the first phase not marked done, and continues. Each phase lists what to do and when it's done.

## Ground rules

1. **Behavior.** Phases A–E change no behavior: same numbers, same rendered text, same saved data. Phase F changes behavior on purpose, one slice at a time. Phase G is cleanup and docs.
2. **Golden policy.**
   - A–E: never update the golden expected files. A failure means the change was wrong. Fix the code, not the expectation.
   - F: each slice lists its expected golden effects. If every difference is one of those, update the files and write a short summary of the differences (what changed, how many values, a few examples) in the Progress log. If anything else differs, stop and report.
   - Don't regenerate golden files just because a test is flaky. Fix the flakiness.
3. **Branches.** One branch per phase (`restructure-b`, `restructure-c`, …), except Phase F, which is one branch, `redesign`, merged only at the end. Merge a phase to `main` when `npm test` is green, then build and push (Pages updates). Fast-forward merges where possible.
4. **Commits.** Small, one idea each, `npm test` green after each. Commit messages say what and why.
5. **Docs.** Keep `ARCHITECTURE.md` true: when code settles a detail it describes, update it in the same commit. Record decisions you had to make in its Decisions section, dated.
6. **Stop and ask the maintainer** (report, then wait) when:
   - a golden difference isn't explained by the current slice's expected effects;
   - a game fact is needed that isn't in `data/rules.js` or the docs;
   - the design and `ARCHITECTURE.md` disagree in a way the Decisions section doesn't settle;
   - a change would delete or rewrite stored user data instead of adding to it;
   - a phase says "The maintainer" (preview checks, licensing, merging the redesign).
   Don't stop for anything else. Make the reasonable call, note it in the Progress log, and keep going.
7. **After each merge to `main`**, tell the maintainer the Claude artifact needs republishing from a claude.ai chat in the Project. From Phase F on, remind them to download a backup from the artifact first.

## Phase A: checkpoint (on `restructure`)

1. Freeze the real-data golden run: copy today's `creatures.json`, `reference.json` and `creature-exp.json` into `tests/golden/data/` and run the real-data capture against those copies, so data updates no longer touch the golden test. Data correctness stays with `generate.js --check`.
2. Update the reference-batch skill and docs: data changes no longer trip the golden test.
3. Add `docs/ARCHITECTURE.md`, `docs/RESTRUCTURE_PLAN.md` and `docs/design/` (supplied by the maintainer) in one commit.
4. Merge `restructure` into `main`, build, commit the built root files, push.

Done when: `main` has the data split, the frozen golden data and these docs; Pages serves the new build.

## Phase B: mechanical split (no logic changes)

1. Cut the main script into files under `src/js/` along its existing sections (constants, helpers, state, weekly, reference hunts, chips, table, render, writes, creature dialog, slots, sessions, goal, board, weekly view, reroll, characters, misc, local db, restore, connect, and the planner split into spots/value, chain, storage, screens). No reformatting.
2. Same for CSS: `src/css/` by section.
3. The assembler joins them back inside the same wrapper function, in the same order.
4. New check: the assembled page is byte-identical to the Phase A `dist/index.html`.

Done when: byte-identical check and `npm test` pass; merged.

## Phase C: modules and tooling

1. Add esbuild (exact pinned version, dev dependency only). `src/main.js` is the entry; the old script body becomes `src/legacy/app.js`, an ES module that still holds the shared variables. The assembler inlines the esbuild bundle (IIFE, target ES2017) in place of the old script.
2. Create the empty folders from `ARCHITECTURE.md` with a README line each.
3. Add `tests/layers.test.js`: per-folder import rules and forbidden globals (`document`, `window`, `localStorage`, `Date.now`, `new Date()` without arguments) in `core/` and `store/`.
4. Add a unit test runner (`node --test tests/unit/`) to `npm test`.
5. Move the data JSON imports into `src/data/` modules and `rules.js`: lift every game constant (pools, task sizes, points, multipliers, bestiary, Warden, raid rates, weekly formula and caps, token cap, Prey, events, default rewards) out of the legacy code with its source comment. UI constants stay.
6. Update `CLAUDE.md` conventions (modules, modern syntax allowed, the layer rule).

Done when: the app runs from the bundle, golden and smoke tests pass unchanged, layer test passes (legacy folder exempt). Merged.

## Phase D: pure core

Extract one primitive at a time into `src/core/`, in this order: `text`, `catalog`, `session`, `rewards`, `metrics`, `score`, `weekly`, `rates`, `reference`, `numbers`, `reroll`, `slots`, `spots`, `occupancy`, `plan`, `explain`.

For each:
1. Move the functions, then replace every hidden input (a shared variable, `profile()`, `weights()`, `itemBySlug`, the clock) with a parameter, following the signatures in `ARCHITECTURE.md`. Adjust the signature if the code shows a better one, and update the doc.
2. The legacy code imports the new function and passes what it used to read globally.
3. Unit tests for the module: normal cases, edge cases (no data, zero weights, unknown creatures), and any rule from `PROJECT_CONTEXT.md` the module implements.
4. Golden unchanged. One commit per module (more if large).

Merge after every three or four modules so `main` stays close.

Done when: everything in the core table lives in `src/core/`, is pure (layer test passes for `core/`), and has unit tests.

## Phase E: store and app layers

1. `store/db.js` (interface plus `claudeDb` and `localDb`), `store/schema.js` (a reader per document type, lifting `readPlState`, `readMark`, `readRecord` and friends), `store/repo.js` (subscriptions, write queue), `store/backup.js`, `store/prefs.js`. Unit tests with an in-memory db.
2. `app/state.js`: one state object fed by `repo` subscriptions. `app/compute.js`: the pipeline from `ARCHITECTURE.md`, replacing `computeDerived` and the globals it set. `app/actions.js`: the current app's write paths as actions.
3. The legacy UI reads from `app/state` and `derived` and writes through actions. It's fine to leave rendering code where it is.
4. `app/views.js`: view models for the current screens where it's cheap. The new ones come in Phase F.
5. Add a golden capture of `compute(state, now)` on the fixture.

Done when: no legacy code touches the db or computes game numbers; golden unchanged. Merged.

## Phase F: redesign (branch `redesign`, merged once at the end)

Build the new UI from `docs/design/` against `app/` and make the model changes in `ARCHITECTURE.md` (State model, Decisions). Old UI and its smoke tests are removed in F1; the numeric goldens stay and keep guarding the math. Add a UI test per screen (jsdom: render from a fixed view model, click, check the action called).

Each slice is model change(s) + migration + view model + screen + tests, one or a few commits:

- **F1 Shell.** `tokens.css`, `base.css`, components, header, tab bar (phone) and header links (desktop), routing between screens, theme setting (`btl.theme`), First run, Characters and settings (sources presets with the `older` switch, world, Taken length, Advanced, backup, credits including TibiaWiki CC BY-SA, TibiaPal and Kusnier). Remove the classic and old planner UI. Migrations: sources, settings, theme. Expected golden effects: none in numbers (`older` defaults on).
- **F2 Goal mix.** Weights 0–5, presets, split text, chip label. Migration of old weights. Expected golden effects: scores and tiers for fixture characters whose old weights were odd numbers; mixed-goal captures re-expressed in 0–5 (update the capture's goal list to the new presets).
- **F3 Bounty.** Modes offers/active, `pickOffer`, `finishedBounty`, `rerolled`, kills left, the Challenging reward field; remove hold and kill progress from logged hunts; plan candidates: all three offers while choosing, only the active bounty once picked; Why? text uses "pick", not "hold". Migration from `board`, `reroll.left`, planner `diff` and `held`. Expected golden effects: plan chains and Why? text; reroll advice where the fixture held an offer with progress from logged hunts.
- **F4 Plan screen.** Chips and inline editors, step chain with Free/Taken/Why?, Hunting now (replaces the timer), Taken spots list, Today's boosts, Time, the Weekly chip, the Data chip, desktop two-column layout. Expected golden effects: none beyond F3.
- **F5 Weekly.** 6/9 slots, kills left, Done, Start a new week, the automatic offer after Monday reset; no kills counted from logged hunts. Migration from the old weekly. Expected golden effects: weekly rows and weekly bonus where the fixture had kills from sessions since reset.
- **F6 Log a clean hunt and user spots.** The full-page log flow, Known spot / New spot / Variation of, `spots/{id}` documents, `spotId` on sessions, variations competing as their own spots, rename/delete user spots, raid counts in Advanced. Expected golden effects: none on the existing fixture (add a user spot and a variation to the fixture in a separate commit and capture them).
- **F7 Spots and spot page.** Search, sort, toggles, badges legend, spot page sections, inline session delete. Expected golden effects: none.
- **F8 Creatures.** Tiers and Avoid, Table, creature panel (spots, sources, Preferred/Unwanted, Avoid, bestiary and Warden done, notes, advanced numbers, pin, min level), Preferred/Unwanted lists with odds. Make solo-only the default everywhere (Decision). Expected golden effects: tier lists and creature numbers where the fixture or real data had duo/team-only spots for a solo character.
- **F9 Finish.** Accessibility pass (keyboard, focus, `aria-*`, contrast), narrow widths down to 320px, light and dark, reduced motion, typographic punctuation, delete dead code, update `PROJECT_CONTEXT.md`, `PLANNER_PLAN.md` (mark superseded parts), `README.md`.
- **F10 The maintainer checks a preview.** Stop: ask the maintainer to have a claude.ai chat publish the `redesign` build as a separate preview artifact and restore a backup into it. Fix what he finds. Merge only when he says so.

Done when: The maintainer approves, `redesign` is merged and built, and the Progress log notes the migration was tested on a real backup.

## Phase G: open-source pass

1. Remove personal details from tracked docs: the claude.ai artifact links and owner details move out of the repo (the maintainer keeps them in their Claude Project files); docs refer to "the maintainer".
2. `.gitignore` backup files (`*backup*.json`, `backups/`). Check fixtures contain only invented characters.
3. `CONTRIBUTING.md`: setup, the layer rule, how to add a feature (contract first), tests, the golden policy, data pipeline and sources.
4. README: what it is, screenshots, credits, "not affiliated with CipSoft", data licenses (`src/data/README.md`).
5. Stop: The maintainer chooses the code license and confirms permission from TibiaPal and Kusnier before the project is announced.
