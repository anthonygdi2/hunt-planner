# CLAUDE.md

Hunt Planner (formerly the Bounty Task tier list), a Tibia hunt planner. Read `docs/PROJECT_CONTEXT.md` (what exists and why) and `docs/ARCHITECTURE.md` (the layers and their rules) before changing anything; the restructure in progress is `docs/RESTRUCTURE_PLAN.md`. Then `docs/PLANNER_PLAN.md` for the hunt planner (the default page) or `docs/REFERENCE_DB_PLAN.md` for the reference hunt data.

## Repo layout

- `src/index.html`: the page shell: fonts, one `{{src/ui/<file>.css}}` line per stylesheet inside `<style>`, the `#app` root, and a `{{src/main.js}}` line where the bundled script goes.
- `src/main.js`: the entry point esbuild bundles. ES modules under `src/` (`src/package.json` sets `"type": "module"`), in the layers of `docs/ARCHITECTURE.md`: `data/`, `core/`, `store/`, `app/`, `ui/`.
- `src/ui/`: `tokens.css` and `base.css` (from `docs/design/`), `dom.js` (element builder, focus-keeping re-render, icons), `components.js`, `shell.js` (header, navigation, hash routes, theme) and `screens/`. One module per screen: plan, spots, spot, creatures, creature, weekly, log, characters, firstRun.
- `src/data/`: `rules.js` (every game number, with its source), `index.js` (`DATA`, `REFERENCE`, `PL_EXP` for the bundle) and the data the page embeds, one record per line: `creatures.json`, `reference.json` (generated, don't edit by hand) and `creature-exp.json`. Sources and licenses are in `src/data/README.md`.
- `tools/assemble.js`: bundles `src/main.js` with esbuild (IIFE, ES2017), puts the bundle and the UI stylesheets into `src/index.html`, replaces each `__BTL_DATA__("<file>")` with that data file, and writes `dist/index.html` (gitignored), one self-contained page as before. Tests call `assemble({ reference })` to swap in a fixture.
- Repo root `index.html`, `manifest.webmanifest`, `sw.js`, icons, `fonts-OFL.txt`: the built GitHub Pages site. Generated by `tools/build.py` from `dist/index.html`; never edit by hand.
- `tools/build.py`: turns `dist/index.html` into the offline build (inlines fonts, adds manifest, service worker, icons).
- `tools/reference/`: reference hunt readings (`readings.json`), the generator that writes `src/data/reference.json` (`generate.js`), the Kusnier video list refresh (`refresh-videos.js`), the batch helper (`batch.js`: next, check, embed and report) and the in-browser frame reader (`browser-helpers.js`). `wiki-exp.json` caches TibiaWiki base exp for the kill-list check and for `creature-exp.json`.
- `.claude/skills/reference-batch/`: the `/reference-batch` skill, which reads the next 10 queued videos, embeds, tests, builds, pushes and reports, batch after batch until an issue needs a person.
- `tests/layers.test.js`: the layer rule (imports and forbidden globals per folder).
- `tests/unit/`: unit tests for `src/` modules (`node:test`, ES modules, no jsdom).
- `tests/ui/`: screens rendered from fixed view models in jsdom (`screens.test.js`: what they show and which action each control calls) and the assembled page end to end with browser storage and a mock of the Claude artifact db (`app.test.js`).
- `tests/data.test.js`: the embedded data and the reference tools, offline (seeds, generated `reference.json`, `PL_EXP` against `wiki-exp.json`, the video refresh, the batch helper).
- `tests/golden.test.js`: golden-output test. Reads `tests/golden/fixture.json` (a backup with two invented characters) with the clock frozen and records what the app computes (`tests/golden/capture.mjs`, through `app/model.js`, no page) for each character, difficulty and goal, in basic and advanced mode, with a fixed REFERENCE and with a frozen copy of the real data (`tests/golden/data/`, so data updates don't touch it), plus `app/compute.js` directly; compares with `tests/golden/expected/`.
- `docs/`: project context and plans.

## Commands

- Install dev deps: `npm install` (esbuild, jsdom, acorn; the page itself has no runtime dependencies)
- Assemble: `node tools/assemble.js` writes `dist/index.html`.
- Test: `npm test` assembles, then runs the layer, data, unit and UI tests (`npm run test:unit` and `npm run test:ui` alone) and the golden test (must pass before any commit). The golden test takes about 15 seconds.
- Golden output: `npm run golden:update` rewrites `tests/golden/expected/`. Only for a change that's meant to alter what the app computes or shows, with the maintainer's OK; never to make a failure go away. During the restructure, follow the golden policy in `docs/RESTRUCTURE_PLAN.md`.
- Build: fetch the fonts once, then `npm run build` (assemble, then `python3 tools/build.py dist/index.html . fonts-cache`):
  ```
  mkdir -p fonts-cache && cd fonts-cache
  npm pack @fontsource/atkinson-hyperlegible
  for f in *.tgz; do tar xzf "$f" && mv package "${f%.tgz}"; done
  cd .. && npm run build
  ```
  Needs Python 3 with Pillow (`pip install pillow`).

## Conventions

- The built page stays one self-contained file with no framework and no runtime dependencies. New code is ES modules with modern syntax (`const`, `let`, arrow functions); esbuild bundles it to ES2017.
- The layer rule (`docs/ARCHITECTURE.md`, checked by `tests/layers.test.js`): imports point down `ui → app → core → data` and `app → store`. `core/` is pure (no DOM, storage, timers or current date; "now" is a parameter); `store/` gets its host objects (`window.claude`, `localStorage`) as parameters. New logic goes in the right layer with unit tests in `tests/unit/`.
- All data access goes through the db API (`doc`, `collection`, `limit`, `onSnapshot`, `get`, `set`, `update`, `delete`). Inside Claude it's `window.claude.use("db")`; outside, `localDb()` emulates it over localStorage. Don't add direct localStorage use except `btl.*` per-device preferences.
- The data model is documented in `docs/PROJECT_CONTEXT.md`. Changes must stay compatible with existing saved data and with backup files (`app: "bounty-task-tier-list"`, version 2; version 1 files still restore).
- UI: follow `docs/design/` (tokens, components, the screen inventory): colors from the token variables of both themes, no modal pop-ups (inline editors, full pages with Back, inline confirms), one gold primary action per screen, 44px tap targets, 16px inputs, never color alone, `aria-*` as the components spec lists, typographic apostrophes and quotes in visible text. Screens render view models from `app/views.js` and call app actions; test narrow widths down to 320px.
- Game numbers (rewards, bestiary, pools) live only in `src/data/rules.js`, each with its source; don't change them without evidence.
- Document shapes and where each lives are in `docs/ARCHITECTURE.md` (State model). Readers in `store/schema.js` accept every shape ever saved; writers write the current shape and keep old fields in step or in place, so an older build still finds its data.
- `PL_EXP` (`src/data/creature-exp.json`) is a copy of `tools/reference/wiki-exp.json` for the creatures in `DATA` (a test checks every value against it); refresh it with `node tools/reference/generate.js --exp` when that file gains creatures.
- Add or extend a check for each feature: unit tests in `tests/unit/` for `src/` modules, a UI test in `tests/ui/` for each screen. The golden test catches unintended changes; it isn't where features get their checks.

## Releasing

1. `npm test`, then build (above).
2. Commit `src/` (with `src/data/`), the built root files and anything else changed; push to `main`. GitHub Pages redeploys in about a minute.
3. Tell the maintainer the Claude artifact copy (the maintainer's synced dev version) needs republishing from a claude.ai chat in the Bounty Task project, from the assembled page: `dist/index.html` as `node tools/assemble.js` builds it at the pushed commit (it isn't in the repo, so the chat runs `npm ci` and the assembler, or gets the file attached). Claude Code doesn't publish it.
4. Keep the TibiaWiki CC BY-SA credit (footer and README).
